# Installed gma500 module: narrow static cross-check

The target's installed `gma500_gfx.ko` was copied by a read-only SSH `cat`, without executing it or opening a GPU interface. The [raw ELF](raw/installed-gma500_gfx.ko) is 205,964 bytes, SHA-256 `7b42a99d157ad00494c358a7663a2daf438ba9fc9a8f2ca5076d28ddeb6adafb`, matching an earlier target-side `sha256sum`. Local `readelf` identifies an i386 relocatable GPL module with `vermagic=5.10.240-antix.1-486-smp SMP mod_unload modversions 486` and Build ID `d8dcb4d38b774ad64799d5e13aaedede069371f3`. A separate read-only [loaded-module sysfs note](raw/loaded-gma500-build-id.note) has the same Build ID. This links the on-disk file and loaded module at the Build-ID level; it is not a source/binary equivalence proof or a register-safety contract.

The first `pciidlist` entry in the ELF `.rodata` has vendor/device `8086:8108`; relocation at `.rodata+0x358` points its `driver_data` to `psb_chip_ops`. The corresponding `psb_chip_ops` dword at struct offset `0x10` is `0x00040000`. In the compiled `psb_pci_probe`, a `0x8000` size is loaded, the ops dword at `+0x10` is added to the BAR0 start, and the result is passed to `ioremap`. This corroborates the audited [source mapping](../../phase7/7.0-ownership-locking.md) for this **installed module and PCI ID**: BAR0 + `0x40000`, length `0x8000`. The source defines `CORE_ID` / `CORE_REVISION` as SGX-relative `0x10` / `0x14` and historical 32-bit accesses, but no read was performed here.

**Gate implication:** requirement 02 now has stronger target-qualified software evidence for the SGX mapping base and retains its scoped register-offset evidence. Requirement 03 retains historical access-width evidence; revision-specific validity remains unproved. Requirement 12's full lifetime/teardown exclusion is not established merely by a Build-ID match. Requirements 04–10 and 13–16 are unaffected. Gate B remains BLOCKED, whitelist `[]`.
