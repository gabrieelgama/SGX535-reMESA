# 7.0 — Ownership and locking in the target source baseline

## Version boundary

The source under [antix-source](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/) is package `5.10.240-antix.1-486-smp-6`. Its 71 gma500 blobs match the archived upstream tree at `d5eca7ebcf6f64c4aebf9684c365c130a3a069b3`. This comparison does not authenticate the installed binary or prove equality of all DRM/PCI/ACPI code. Installed-kernel identity remains UNVERIFIED; the existing [passive verification plan](../../experiments/bringup0/PASSIVE-KERNEL-VERIFICATION.md) is still needed.

Current Linux `9b87fdc9…` has different PM and IRQ code. Its managed lifetime, PM helper semantics, and handler lock coverage must not be assigned to 5.10.240.

## Mapping and lifecycle

CONFIRMED software evidence, P7-001: [psb_drv.c](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/psb_drv.c), lines 210–245 and 428–482; [psb_drv.h](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/psb_drv.h), 51–64; [psb_device.c](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/psb_device.c), 319–348.

The PCI driver enables the function, allocates a DRM device, sets driver data, and calls `psb_driver_load()` before `drm_dev_register()`. It maps BAR0 into `vdc_reg` and maps BAR0 plus the Poulsbo SGX offset `0x40000`, length `0x8000`, into `dev_priv->sgx_reg`. The same driver holds both virtual mappings. These mapping calls do not themselves prove a separate exclusive BAR reservation or safe access in every PM state.

Load continues through chip setup, PM setup, GTT/MMU setup and SGX writes before IRQ installation and modesetting. Remove unregisters DRM, unloads, then drops the DRM reference. Unload frees MMU/GTT state and unmaps `sgx_reg` before freeing private data (lines 147–207). A retained pointer alone does not pin that lifetime.

The observed BAR0 and source offset imply a candidate physical SGX base of `0xd8140000` **by arithmetic only**. This is INFERRED, not a mapping created or an address authorized for use.

## Access and synchronization inventory

| path | actual source behavior | limit for a future observer |
|---|---|---|
| probe/load | SGX mapping at lines 242–245; chip PM, MMU/reset and base writes later | a point after mapping and before IRQ/DRM publication has fewer exposed clients, but power prerequisites and core driver lifecycle exclusion are not established |
| PM | `power_mutex` surrounds suspend/resume; `power_ctrl_lock` surrounds display claim/release | different locks; neither is demonstrated as a universal SGX protocol |
| IRQ | handler releases `irqmask_lock` before SGX status reads and acknowledgement | taking that lock alone does not exclude the SGX handler |
| MMU | semaphore serializes PD/context/flush paths | IRQ, 2D and chip-setup accesses do not all participate |
| 2D/fbdev | `lock_2d` surrounds FIFO submission/sync; code can reset SGX | a functioning KMS/fbdev driver is not an idle SGX owner |
| KMS/work | load enables modesetting, fbdev and polling after IRQ installation; private state contains hotplug/ASLE work | no blanket exclusion follows from a DRM file reference or a modeset lock |
| remove | DRM unregistration precedes private mapping destruction | future instrumentation must be excluded from teardown, not merely hold the address |

Sources: P7-001; P7-002 [power.c](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/power.c):38–75,188–296; P7-003 [psb_irq.c](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/psb_irq.c):198–249,252–407; P7-004 [mmu.c](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/mmu.c):102–140; P7-005 [accel_2d.c](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/accel_2d.c):35–60,95–118,259–285,313–352; P7-001 [psb_drv.h](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/psb_drv.h):246,554.

In this version `psb_irq_uninstall()` programs masks; it is not a call to `free_irq()` or `synchronize_irq()` in the inspected function. The system-suspend call to it must not be summarized as proof that every in-flight SGX handler has completed.

## Adversarial interleavings

These are analysis timelines, not reproduced races:

| observer CPU | other context | missing protection |
|---|---|---|
| takes `irqmask_lock` | IRQ has already released that lock and proceeds to SGX reads | no exclusion of the rest of the handler |
| sees `display_power=true` | suspend under `power_mutex` observes zero users and proceeds toward D3hot | a snapshot and a separate display-claim lock do not establish a common observation protocol |
| retains `sgx_reg` | remove unregisters and unmaps it | no proven lifetime guard |
| takes an MMU semaphore | 2D path holds `lock_2d` and accesses SGX | unrelated resource-specific lock |

A future point inside gma500 would avoid inventing a second mapping owner. That is an architectural preference (INFERRED), not a safe point identified for execution. No complete lock order or runtime hook is approved.
