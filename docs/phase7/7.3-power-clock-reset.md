# 7.3 — Poulsbo power, clocks and reset

## What the software tracks

CONFIRMED software behavior (P7-002): 5.10.240 sets `display_power=true` and `suspended=false` during PM setup. Its query returns the display flag. These are software state variables, not SGX island or clock measurements. The Poulsbo `power_up/down` callbacks simply return zero (P7-011, [psb_device.c](../phase4-2-data/antix-source/drivers/gpu/drm/gma500/psb_device.c):239–247).

TVZ runtime status `active` establishes a reported Linux PM state only. SGX ON, SGX OFF, register-interface clock enabled/gated, and reset asserted/released are all NOT-TESTED in this run. No existing passive interface in the inspected target source establishes those physical states.

## Static transition model

This is a model of software calls, not an executable sequence. Every edge is explicitly scoped.

| edge | classification | source and remaining gap |
|---|---|---|
| PCI probe → enable device → map VDC/SGX | CONFIRMED software order | P7-001; internal SGX state after mapping UNKNOWN |
| PM init → display flags → Poulsbo 2D clock-gating read/modify/write | CONFIRMED software order | P7-002/P7-011; does not establish register-interface clock prerequisite |
| load → GTT → MMU → `psb_do_init` reset/BIF work → base writes → IRQ/KMS | CONFIRMED software order | P7-001/P7-005; not a mandatory hardware order |
| bound state → suspend callback → mask IRQs/save display → disable PCI → request D3hot | CONFIRMED software order | P7-002/P7-003; SGX state preservation and in-flight IRQ exclusion UNKNOWN |
| D3hot software state → request D0/restore PCI → restore GTT/display → IRQ callbacks | CONFIRMED software order | P7-002; not proof of SGX microkernel/MMU recovery |
| runtime suspend/resume → system suspend/resume helpers | CONFIRMED software dispatch | P7-002, `power.c:299–331`; availability of a specific runtime transition on the running system UNKNOWN |
| reset assertion writes → delay/readback → reset release writes | CONFIRMED software order | P7-005; ID-read accessibility while reset is asserted UNKNOWN |
| display active → SGX powered or clocked | UNKNOWN | no such physical-state implication established |
| SGX off → SGX on with a safe register aperture | UNKNOWN | missing platform sequence, clock predicate and CPU completion contract |

A `power_mutex`-protected suspend and a `power_ctrl_lock`-protected display claim are different protocols. See [7.0 ownership](7.0-ownership-locking.md). The code does not justify wrapping a new read with a display helper and calling it safe.

## Historical PSB/DDK/EMGD comparison

P7-006 rechecks the Phase 6.1 `TRAP_SGX_PM_FAULT` finding in the target-version source itself: the disabled branch reads `apm_base + PSB_APM_STS`, masks `0x3`, warns, and then reads SGX. It contains the literal `melay(1000)`; it was not enabled or tested. The code supplies neither an APM field contract nor a fail-closed read guard. No APM port read is proposed.

P7-012: the historical Poulsbo DDK [sysconfig](../archaeology-data/PSYSC.txt):1763–1897 has a non-`SUPPORT_DRI_DRM_EXT` branch that disables/uninstalls interrupts, unmaps system registers and suspends PCI; the reverse path relocates/remaps and reinstalls. Under `SUPPORT_DRI_DRM_EXT`, device OFF releases graphics then display references; leaving OFF acquires display then graphics references and unwinds display on failure (1916–1979). These are **CONFIRMED software calls** to external OSPM integration, not recovered island-control implementations. The core and display are named separately; independent electrical power behavior is still UNKNOWN.

The EMGD [Poulsbo power source](../poulsbo-data/EMGD_drm_emgd_state_power_plb_pwr_plb_c.txt):83–121 leaves its D0–D3 switch cases empty, while initialization writes clock-gating controls (P7-013). A no-op in this component is not proof the complete EMGD stack never controls power.

## Clocks and reset

| source term | what it establishes | what remains UNKNOWN |
|---|---|---|
| `gma_get_core_freq` | selector write/read and backlight PWM consumer, P6-001/P6-002 | physical SGX execution/interface clock and enable state |
| `SYS_SGX_CLOCK_SPEED` | Poulsbo software timing constant, P6-003 | measured frequency and accessibility |
| `SGX_FEATURE_AUTOCLOCKGATING` | SGX535 feature-selection macro, P7-010 | behavior of ID reads under gating |
| `CLKGATECTL` in target gma500 | 2D field manipulation, P7-011 | full domain map or safe clock checks |
| `SGXResetSleep` | software wait expressed as 100 SGX clocks, P7-009 | clocks actually running on Dell or CPU completion when absent |
| BRN23944 / BRN23410 | reset fault-handling / TA context workarounds in DDK code, P7-009 | applicability to target silicon and the first ID read |
| BRN22693 | early-SGX535 build selector in EMGD, P7-008 | applicable read trigger, workaround and revision coverage |

No source in this review proves either ID can be read before GTT, MMU, BIF, firmware or microkernel initialization. Nor does historical ordering prove all those operations are hardware prerequisites.
