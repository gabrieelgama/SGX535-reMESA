# Historical stack pairing: strongest supported match

The two retained `xpsb-glx` 0.18 ELFs are an **exact same-archive pair**, not an authenticated complete installation. Both embed `5.0.1.0046` (`psb_dri.so` file offset `0x25a7e4`; `Xpsb.so` `0xcfea`). The public RPM Fusion [PSB kernel source package](source-provenance.md) `psb-kmod-4.41.1-10.fc11.10` contains `psb-kernel-source_4.41.1.orig.tar.gz` whose `psb_drm.h:37` also declares `PSB_PACKAGE_VERSION "5.0.1.0046"` (P7D-004). This is the strongest recovered **release-family correlation**. It does not prove those source bytes built the installed kernel module paired with either ELF.

|---|---|---|---|
| retained `psb_dri.so` and `Xpsb.so` | same 0.18 source archive; matching embedded `5.0.1.0046` | direct command indices 0/1/2/3 and sizes; separate Xorg/DRI entry points | exact archive membership; runtime compatibility not tested |
| PSB kernel source `4.41.1` | header package label `5.0.1.0046`; `psb_drv.h:77–78` driver 4.41 | header indices 0/1/2/3; i386 `CMDBUF` 144 bytes, `XHW_INIT` 20 bytes, `scene` 20 bytes match observed direct-call sizes | **compatible-family, strong**; no matched kernel binary/build manifest |
| earlier retained PSB kernel snapshot | header label `5.0.0.0045` | similar request family and sizes | historical predecessor, weaker than `4.41.1`; not an exact match |

| public `libdrm-poulsbo` 2.3.0 source | final `-10` and testing `-11` source tarballs have identical SHA-256; bundled `psb_drm.h` labels `2.2.0.32L.0027` | generic BO/fence wrappers and command-index dispatch match imported symbol family; bundled PSB header predates the 5.0.1.0046 detear layout | wrapper-source candidate only; exact linked `libdrm.so.2` **UNKNOWN** |

The 4.41.1 header defines `PSB_DETEAR` (`psb_drm.h:193`), making `video_info` seven 32-bit fields on i386 (`:197–203`). Its command argument has four 64-bit fields, twenty-one 32-bit fields and that 28-byte video tail: `32 + 84 + 28 = 144` (`0x90`, `:221–263`). `XHW_INIT` has five 32-bit fields on i386 (`0x14`, `:265–273`), and `drm_psb_scene` five (`0x14`, `:206–212`). The retained binaries' direct libdrm calls use those sizes. This confirms **layout-size agreement**, not field-by-field compatibility of an exact build or successful ioctl dispatch (P7D-005).

The candidate `drmCommandWrite` call for `XHW_INIT` uses a write-direction ioctl word, while the 4.41.1 `psb_drv.c:88–90` descriptor uses `DRM_IOR`. The bundled DRM core explicitly disables full-word equality checking, dispatches private requests by `_IOC_NR`, and copies input according to the *caller-supplied* direction and size (`drm_drv.c:607–659`). The candidate XHW-init handler only consumes the argument and returns status (`psb_xhw.c:416–470,516–528`). Thus this direction difference does **not** by itself prevent `XHW_INIT` dispatch in this candidate source tree. This corrects the earlier unresolved-dispatch wording; the exact libdrm/kernel builds paired with the retained ELFs remain UNKNOWN.

The focused [XHW init trace](xhw-init-frozen-draw.md) adds a field-level fingerprint: the retained `Xpsb.so` sends the candidate's operation-zero and BO-handle pair, allocates a `0x84`-byte communication BO matching the candidate `drm_psb_xhw_arg` size, and dispatches operation numbers 1/2 to scene-info and scene-bind/fire routines. This strengthens the **compatible-family** classification. It does not authenticate the exact kernel, DDX or libdrm binary, and the source's optional XHW-init tail is not initialized by this retained ELF.

The RPM Fusion 2009 source index lists contemporaneous `xpsb-glx-0.18-5`, `libdrm-poulsbo-2.3.0-10`, `psb-firmware-0.30-4` and `psb-kmod-4.41.1-10.fc11.10`; the recovered DDX spec names those package families. Package co-presence is **not** a build manifest. In particular, the retained xpsb spec is 0.18-4.1, not the indexed 0.18-5 release; no replacement xpsb package was downloaded. The public libdrm source's older PSB header, the DDX loader-symbol mismatch, and absent exact built DDX/libdrm/kernel binaries prevent an exact five-way pairing.

The retained `Xpsb.la` names only `-lpthread` in `dependency_libs`; `Xpsb.so` has no direct `DT_NEEDED` for libdrm. Its ELF version-needs table names GLIBC versions through `libc.so.6` and `libpthread.so.0`, not a libdrm symbol version. These metadata cannot pin the runtime provider of its imported DRM helpers.

The contemporary [gma500 reference driver](../../gma500-current-state.md) is a separate display-oriented implementation. This historical ABI is not attributed to the Dell's installed module.

The later [draw-to-submit trace](../psb-dri-re/draw-to-submit.md) resolves a private indirect call within `psb_dri.so`. It introduces no new build-identity evidence and does not change the release-family pairing or the mismatches above.
