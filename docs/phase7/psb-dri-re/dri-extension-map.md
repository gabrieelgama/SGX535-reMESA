# Historical DRI ABI — checkpoint B

The exported `__driDriverExtensions` at ELF VA `0x002bb1bc` is a four-entry 32-bit pointer array: `0x002b9620`, `0x002b3280`, `0x002b3294`, then NULL. The three descriptors are `DRI_Core`, `DRI_Legacy`, and `DRI_DRI2`, all version 1. A separate five-entry descriptor list at `0x002bb2d0` contains `DRI_ReadDrawable`, `DRI_CopySubBuffer`, `DRI_SwapControl`, `DRI_FrameTracking`, and `DRI_MediaStreamCounter`, then NULL. The driver-specific screen initializer at `0x0004be92` assigns this list address to screen offset `+0x44` after a device-private size check. This connects the list to a successfully initialized legacy screen; it does not establish that every optional callback succeeds at runtime.

The [machine-readable field map](dri-extensions.csv) records eight distinct descriptors, 23 non-NULL callback fields and their original ELF VAs, file offsets, and Ghidra-style shifted names. The [function map](function-map.csv) retains those 23 callback addresses and adds 28 reviewed Poulsbo/SGX entry points; body-level findings are stated separately from ABI field roles. `DRI_ReadDrawable` is an extension-name/version marker with no callback fields in this ABI definition.

The field layout comes from the public Mesa 7.4.4 `include/GL/internal/dri_interface.h`, sections `__DRIextensionRec`, `__DRIcopySubBufferExtensionRec`, `__DRIswapControlExtensionRec`, `__DRIframeTrackingExtensionRec`, `__DRImediaStreamCounterExtensionRec`, `__DRIcoreExtensionRec`, `__DRIlegacyExtensionRec`, and `__DRIdri2ExtensionRec` (header lines 103–195, 467–509, 566–593, 666–685). I obtained the official historical [MesaLib 7.4.4 release archive](https://sourceforge.net/projects/mesa3d/files/MesaLib/7.4.4/) for comparison in `/tmp`; its MD5 `b66528d314c574dccbe0ed963cac5e93` matches [Mesa's published 7.4.4 checksum](https://docs.mesa3d.org/relnotes/7.4.4.html). No archive source was copied into this project. The byte layout and descriptor names/versions in the target independently match this historical definition. A current Mesa header was not substituted.

For example, the core descriptor at `0x002b9620` has `createNewScreen`, `createNewDrawable`, and `createNewContext` fields NULL; its `getExtensions` pointer at field offset `0x10` is ELF VA `0x000213a0`. The legacy and DRI2 descriptors provide alternate constructors. Static disassembly of `0x000213a0` shows a return of the pointer stored at screen-object offset `0x44`. This confirms the callback's immediate action and aligns with the historical ABI role. The driver-specific initializer at `0x0004be92` supplies the five-entry list. This does not establish that all listed optional callbacks succeed at runtime.

The earlier GUI notes used addresses `0x10000` above the raw ELF VAs: GUI `0x002c9620` corresponds to ELF `0x002b9620`; GUI `FUN_000313a0` corresponds to ELF `0x000213a0`. Treating GUI addresses as ELF VAs would land in unrelated bytes. The [parser](../../../tools/psb-dri-re/dri_map.py) asserts the root/list pointer arrays and the descriptor names before exporting roles. Future function classifications retain both address forms.

The [all-name pointer scan](dri-name-pointer-scan.csv) also found four `DRI_*` strings without aligned direct descriptor pointers in `.data.rel.ro`, `.data`, or `.rodata`: `DRI_GetDrawableInfo`, `DRI_Damage`, `DRI_SystemTime`, and `DRI_DRI2Loader`. They may be loader-side names. Their strings are CONFIRMED; no extension descriptor for them is confirmed in this ELF. This scan prevents treating a name string as an exposed callback table, while leaving more indirect constructions UNKNOWN.

**DRI2 advertisement is not DRI2 availability.** Disassembly at `0x00021ca5–0x00021caf` loads the driver API pointer from GOT slot `0x002ba9cc` and tests its field at offset `0x3c`; a zero value branches to the null return at `0x00021e02`. The slot's recorded pointer is `0x002b9660`, and that read-only driver API table has zero at `+0x3c`. Mesa 7.4.4 `dri_util.h:229` names that field `InitScreen2`. This is CONFIRMED static behavior of the shipped bytes: the exported `DRI_DRI2.createNewScreen` callback cannot proceed through its normal constructor with this fixed table. It does not say what a different historical build supplied or what the Dell executed.

This graph describes a historical 2009 DRI interface, not a suitable modern Mesa ABI by default. Descriptor presence shows advertised callback pointers; whether a callback reaches PSB kernel command submission remains a separate control-flow question.
