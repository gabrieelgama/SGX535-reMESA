## Forward branch elimination

At `0x00033490`, the first optional prelude requires fragment input mask bit 0, which the selected primary-color-only program lacks; the second requires bit 3 and the optional fog/secondary prelude requires an option flag excluded by the frozen path. Its END-adjacent insertion requires output mask bit 2 and is excluded. The loop calls `0x00031381` for the MOV and END, which increments the record count once per selected instruction. The zeroed allocation supplies the untouched fields, subject to checking the source/destination helper writes. This supports exactly two source records **before** the USC parser's own possible insertions; it does not fix the compiled count.

The compiler option buffer is not an abstract constant: `0x0002c852` constructs a 60-byte fragment key before calling `0x00033490`. Its first byte combines three tests: six retained-context values at a private state object `+0x38/+0x3c/+0x44/+0x48/+0x50/+0x54`; a condition involving `context +0x634` `+0x2c`, fragment program `+0x11dc`, and `OutputsWritten` at `+0x20`; and several state bytes under `context+0x634`. This key also selects the result cache. The specified MOV/END opcodes alone therefore do not identify every compiler input; each key bit must be evaluated for the frozen state, not silently set to zero. `0x00033490` maps that key to compiler fields: stack `local_f0` starts at `0x4a` (becomes `0xca` if key bit 1), `local_4c` is selected from key bit 1/2, `local_58` is set to one, and parameter/texture counts enter `local_54/local_50`. `0x0003503d` then uses those stack fields to configure USC. No bit has yet been declared an external irreducible input.

The `0x0002c852` inputs are less arbitrary than their stripped names suggest. Its `context+0x634` bytes `+0x18…+0x1b` form a four-channel on/off mask also used in `0x0002bfdf` (`psb_state_mteusse.c` assertion context). With all color channels enabled and the frozen blend/alpha features disabled, the key's optional bit-2 path is **conditionally** absent. The first bit compares front/back state fields at `context+0x65c`; this looks stencil-related in `0x0002bfdf`, but the exact inactive-state field values have not been established. Crucially, `0x00033490` and `0x0003503d` use key bits 1 and 2 to select compiler setup; no direct compiler-setup read of key bit 0 is yet seen. This is a branch constraint, not proof that key bit 0 cannot affect any later compiler input.

The selected key bits 1/2 can now be evaluated with the historical Mesa 7.4.4 `gl_colorbuffer_attrib` layout (`src/mesa/main/mtypes.h:566–615`, `config.h:231`, four draw buffers). `context+0x634+0x2c` is `AlphaEnabled` (false); `+0x18…+0x1b` are `ColorMask[0..3]` (all enabled); `+0x38` is `BlendEnabled` (false); and `+0x6a` is `_LogicOpEnabled` (false). In that layout, `program+0x11dc` is `UsesKill` after `FogOption` (`mtypes.h:1943–1950`), false for the MOV/END input, while `OutputsWritten &4` is false. Thus `0x0002c852` makes key bits 1/2 zero for the frozen state. `0x00033490` uses only those bits for `local_f0=0x4a` and `local_4c=1`; bit 0 remains unresolved but has no observed read in the selected converter/wrapper path. This is a defensible binary/source ABI correlation for this exact Mesa layout, not an assertion about every historical build.

The wrapper's stack offsets can be translated without guessing from `param_4=&local_144` in `0x00033490`: `param_4+0xec` in `0x0003503d` is `local_58=1`; `+0xf0` is `local_54`, four times the Mesa parameter count; `+0xf4` is `local_50` (parameter bytes plus 12 per active texture); `+0xf8` is `local_4c`; and `+0xfc` points at the allocated UniFlex list. If compiler key bits 1/2 are zero, the observed setup is `local_f0=0x4a`, `local_4c=1`, `local_58=1`, and software target `(3,111)`.
