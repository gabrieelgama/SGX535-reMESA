# Generated formats: what the static evidence specifies

This is a field inventory, not a decoder or an implementation. Binary addresses refer to retained `psb_dri.so` SHA-256 `74ca42991906741ee91be1bc088ae0b142fa71b6a85658c5dad0851ce50dd0d8`. Candidate kernel declarations are from public `psb-kernel-source-4.41.1` (`psb_drm.h` SHA-256 `b4aeb1f85c5609c5811447f2c1ea691a4dbaedb439955df507b51b8302769494`). The two ELFs and this source share `5.0.1.0046`, but no exact linked stack is authenticated. [The field CSV](format-fields.csv) records offsets, producers, consumers and evidence scope.

| layer | established format/operation | specification limit |
|---|---|---|
| PDS-related vertex output | `0x00040355` reserves a separate output block, uses `0x000381a0` for one/two-part address data, records relocations and emits fixed words. See the [bounded layout](bounded-path-closure.md). | Some literal words and formulas are known. Full format, target revision and required execution ordering are UNKNOWN. |
| USE/USSE instruction buffer | `0x00030ffd` reserves zeroed eight-byte instruction slots; `0x00030fb7` closes them. `0x0002fabd` has `psb_use.c`/`use_next_inst` assertions. | Earlier PDS label corrected by P7F-003. Complete instruction bytes, encoding and SGX535 revision applicability are UNKNOWN. |
| USC/USSE | `0x001fb7af` and helpers generate words and track instruction counts; `0x00034ce4`/`0x0003503d` consume compiler results. | Generator existence is CONFIRMED; a licensable, independently specified ISA and minimum shader binary are UNKNOWN. |
| TA/index record | `0x0003b890` reserves `0x14` bytes: word 0 combines primitive input, `0x81400000` and count; words 1 and 3 are relocation destinations; word 2 receives an argument; word 4 combines several source fields. | Producer and formulas are visible. The hardware meaning of every mask/bit and revision applicability are not independently established. Do not name the packet solely from the constant. |
| scene | `0x00027060` allocates a `0x5d0`-byte private scene and acquires a 20-byte DRM scene record via `0x000276a5`. The candidate header's `drm_psb_scene` has five 32-bit fields (`psb_drm.h:206–212`). | Private structure is only partly mapped. Pool reuse, complete flags and all lifetime/error transitions remain incomplete. |
| scene final record | `0x0002a39a` reserves eight bytes and writes `0xc0000000` in its first word before submit. | P7G-002 shows that only the first word is committed; the second reservation word is not emitted. Hardware semantics remain UNKNOWN. |
| command argument | `0x00037b51` zeroes a 0x90-byte stack region and calls `drmCommandWrite` index `0` with it. The candidate `drm_psb_cmdbuf_arg_t` fields/offsets are defined by `psb_drm.h:221–263`, with a `PSB_DETEAR` tail. | The binary's selector `0` writes engine value `3`; candidate `PSB_ENGINE_TA=3`. Field-wise exact-release and actual libdrm/kernel acceptance are not proven. |
| relocation record | `0x00037854` advances a relocation cursor by ten 32-bit words (`0x28` bytes), calculates a destination word or placeholder `0x67676767`, and fills at least words 0–7. The candidate header's 10-field `drm_psb_reloc` is at `psb_drm.h:143–154`; candidate kernel consumes it at `psb_sgx.c:631–782`. | Source/binary layout is strongly consistent; exact producer meaning for all ten words and revision-specific USE/PDS address rules need further proof. |
| BO validation | `0x00037b51` links validation entries before submitting. Candidate `drm_bo_op_arg` has a 64-bit `next`, request/reply union and handled field (`drm.h:851–858`); candidate kernel follows `next`, requires `drm_bo_validate`, and validates flags/mask/hint (`psb_sgx.c:410–500`). | The complete binary-side entry layout, every BO flag and presumed-offset feedback contract are not yet mapped against an authenticated libdrm build. |
| fence/sync | Submit wrapper processes a returned fence and can construct a `SuperFence`; candidate kernel returns fence feedback. Historical `drmFence*` imports and candidate ioctl numbers are in [the ABI map](../xpsb-re/libdrm-kernel-abi.md). | Full ordering, object lifetime and error behavior across the exact paired library/kernel are UNKNOWN. |
| XHW | `Xpsb.so` uses an out-of-band shared BO and direct indices `1`/`2`; candidate `psb_drm.h:265–334` and `psb_xhw.c` describe operations. | The candidate kernel requires XHW readiness for TA scheduling (P7G-013); exact cross-build initialization and request/reply ordering remain UNKNOWN. See [bootstrap](../xpsb-re/bootstrap-dependencies.md). |

The candidate kernel makes a useful distinction: `psb_sgx.c:487–508` treats one raster/TA register stream as offset/value pairs and writes the value to the offset after checks, while `psb_sgx.c:519–574` copies user BO words through engine-specific handling. That **source behavior** is not a general authorization to reproduce or submit a stream, and it does not decode the generated PDS/USSE bytes. Hardware packet and program formats are **not complete enough** for a minimal clean-room 3D draw. The well-defined historical ioctl envelope and selected relocation fields can support an offline interface specification only.


The [P7G word map](frozen-draw-formats.csv) records the later width-eight triangle and the corrected committed terminal length. It does not establish complete fragment, PDS or scene formats.
