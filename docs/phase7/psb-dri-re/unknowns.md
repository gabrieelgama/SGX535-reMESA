## Bounded pre-implementation pass (P7F)

P7B-U02 is further constrained, not closed: `0x00029251` dispatches scene dirty bits into the selected eight-position setup branch, whose CPU-side vertex/index copies, two USE/USSE instruction slots and selected TA literals are now recorded [byte by byte](bounded-path-closure.md). P7F-010 also resolves `0x0002d124` as a dirty-state atom callback with a matching generic atom walker `0x0004f3ef`; context creation installs the 17-entry atom list (P7F-011), while P7G-010 subsequently closes the historical DrawElements entry. Valid shader/state inputs, PDS/USSE semantics, broader scene state, relocations and sync still block a one-draw specification. P7B-U01/U03/U05 remain UNKNOWN. P7B-U04 is unchanged: these generated bytes are not a confirmed static firmware/microkernel payload.

The earlier description of `0x00030ffd`/`0x00030fb7` as a PDS instruction buffer was incorrect. `psb_use.c`/`use_next_inst` assertions identify their eight-byte slots as USE/USSE instructions (P7F-003). `0x00040355` separately emits a PDS-related vertex output block. This changes the classification of that **buffer**, not the physical SGX revision, safety gate, or the requirement for a complete program contract. See the ranked [remaining gaps](preimplementation-decision.md).
