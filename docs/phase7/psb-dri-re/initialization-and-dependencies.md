# Screen initialization and missing components — checkpoint G

The shipped ELF's exported root is `__driDriverExtensions` at `0x002bb1bc`. Its legacy constructor `0x00021e0e` allocates a DRI screen, copies the 16-pointer driver API table at `0x002b9660`, records a DRM fd and calls the table's `InitScreen` entry. The driver-specific initializer at `0x0004be92` checks a device-private `PsbDRIRec` size of `0x20`, allocates 0x50 bytes of screen-private state, copies fields from the supplied record, attaches the five-entry screen extension list and builds framebuffer configurations. These are **CONFIRMED binary operations**. Their preconditions and the X-server side of the supplied `PsbDRIRec` are not fully reconstructed.

The DRI2 descriptor is exported, but its `createNewScreen` callback tests the `InitScreen2` field of that same fixed API table. It is zero in this binary, so the normal DRI2 constructor returns NULL. This is a static result for this artifact, not a statement about every version of xpsb-glx.

Direct `DT_NEEDED` libraries are `libm.so.6`, `libpthread.so.0`, `libexpat.so.1`, `libdl.so.2`, `libdrm.so.2`, and `libc.so.6`. There is no direct dependency named `libpvr`, `libsrv_init`, or `libusc`. The USC/USSE generation code appears embedded, as shown by the [code evidence](sgx-specific-findings.md). The package also contains an `Xpsb.so` X-server component; its precise shared-record and kernel relationship has not been established by this ELF alone. `libdrm.so.2` implements imported BO/fence helpers, so this binary alone cannot enumerate every underlying ioctl.

The Phase 7 [Services/DDK initialization trace](../7.5-firmware-microkernel.md) remains a separate historical source family. This DRI file does not by itself identify the matching `DevInitSGXPart2KM` producer, scripts or microkernel payload. An absence of `PVRSRV` in direct dependencies does not prove no related contract exists elsewhere in the stack. Conversely, the binary's scene and shader code cannot be treated as evidence that the DDK Services path was used unchanged on Poulsbo.

The interface gap for a clean implementation is now narrower on the userspace side: historical DRI callbacks, two direct libdrm requests, buffer/relocation construction, a 2D swap path, and USC/PDS-related generation are locatable. The exact paired X-server and kernel build, 3D scene submit path, SGX initialization inputs, firmware/microkernel identity and hardware safety contract remain UNKNOWN.
