# Frozen fragment compiler: focused static trace

This checkpoint continues the P7G triangle analysis. Addresses are ELF virtual addresses in the retained `psb_dri.so` (SHA-256 `74ca42991906741ee91be1bc088ae0b142fa71b6a85658c5dad0851ce50dd0d8`); Ghidra's project address is ELF VA plus `0x10000`. The binary was only parsed and decompiled. No historical code or hardware was executed.

## Input and first transformations

The existing [frozen-draw closure](frozen-draw-closure.md) establishes the fixed-function no-texture input: Mesa instruction opcodes `0x2b` (primary color to output, mask `0xf`) and `0x19` (END). This remains a CPU-side input, not compiled USSE. The converter at `0x00031381` maps those numeric opcodes to UniFlex `0x48` and `0x35`; the ordinary path builds 0x84-byte records. `0x000310e0` links the generated records through the pointer at record offset `+0x80` and terminates the final link with zero. **CONFIRMED** as retained-binary behavior. The exact record contents still depend on the source/destination conversion helpers (`0x000312a0`, `0x0003130a`) and the fixed-function builder's register values. They must be evaluated for this precise input before claiming exact compiler inputs.

There is a conditional extra record immediately before END in `0x00033490`, but it requires program `OutputsWritten & 4`. The no-texture builder sets `OutputsWritten` to `1 << FRAG_RESULT_COLR`; the candidate Mesa 7.4.4 definition has `FRAG_RESULT_COLR = 0` (`src/mesa/main/mtypes.h:306` and `texenvprogram.c:1072`). The binary builder at `0x000aa97c` also initializes this output mask to `1`. Thus this particular insertion branch is excluded for the frozen input. This is a source/binary correlation, not an assertion that *all* implicit instructions elsewhere in the compiler are absent.

The same source defines `FRAG_ATTRIB_COL0 = 1` and `PROGRAM_INPUT = 4` (`mtypes.h:254–263,1840–1851`); its no-texture `SRC_PREVIOUS` branch selects primary color (`texenvprogram.c:676–685`). In the binary converter, the ordinary fragment target (`0x8804`, not the alternate `0x8620` branch) uses `0x00033100` for destination and `0x00033257` for source. For packed destination file `5`, index `0`, `0x00033100` assigns UniFlex destination class `6`, index `0`; for packed source file `4`, index `1`, `0x00033257` assigns source class `1`, index `0` when the no-texture option byte has bit `8` clear. These are **CONFIRMED conditional CPU mappings** from the binary and historically matched Mesa structure; the complete UniFlex record still needs its swizzle and remaining fields checked before treating it as a reproducible compiler input.

The opcode table initialized at `0x00031381` has entry `0x002d9f78 = 1` operand and `0x002d9f7c = 0x48` for Mesa opcode `0x2b`; the END switch case sets `0x35` directly. The binary Mesa instruction initializer `0x0010c3b7` zeroes each 64-byte record and installs the source swizzle default `0x688`. This narrows the first UniFlex record to one source rather than an unbounded operand list. It does not establish the final USC register allocation or emitted instruction count.

The source converter's swizzle helper `0x000311b6` maps the default `0x688` component selectors `[0,1,2,3]` back to `0x688` for this single-source path; the opcode-table operand count is `1`, so the conversion call's swizzle-mode argument is zero. This closes that one source field **conditionally on the frozen key**. Register class/index and this swizzle are compiler *input* descriptors, not final assigned USSE registers.

The first 0x84-byte UniFlex input record can now be reduced further. The converter's array is initially zeroed by `_mesa_calloc` at `0x00033490`; `0x00031381` and the ordinary descriptor helpers then make these nonzero fields for the frozen MOV:

The END record has opcode `0x35` at `+0x00`, a zero next pointer at `+0x80`, and otherwise retains zero-initialized fields. This is a **CPU-side intermediate layout**, not a copyable GPU program; exact bits should still be checked against disassembly before declaring the entire 0x84-byte record closed. In particular, no conclusion about the compiler's output count follows.

The wrapper at `0x0003503d` selects software target pair `(3,111)` and calls `0x001c6b56`. Its output copies the primary instruction pointer/count from the compiler output into result `+0xa8/+0xac`, and secondary pointer/count into `+0x1c0/+0x1c4`. Other resource and mapping fields are copied into `+0xb0…+0x1dc`. These are result layouts, not yet their values. The selector pair is not a measurement of the physical core revision.

## Where the words are determined

`0x001c6b56` initializes the compiler state and calls `0x001c606c` before `0x001fb7af`. The former parses the UniFlex input (`0x001c3ba5`) and runs a sequence of lowering, optimization and register-related passes. Its direct call graph contains 38 distinct callees, including `0x0022923e`, `0x0022cc74`, `0x00227461`, `0x00226d79`, `0x0022771f`, `0x001ef2ee`, `0x001cc814`, `0x001d2745` and `0x001c95f7`. This establishes that source opcode `0x48` cannot be mapped straight to a final eight-byte word pair. The selected branch outcomes and transformed IR have not yet been proven.

The parser at `0x001c3ba5` copies ordinary 0x84-byte UniFlex records into its own allocation, links them again and constructs a control-flow representation. It also conditionally appends instructions related to program outputs near its end (notably the branch involving compiler-state word `+0x1c` and output at `+0x1f`). **CONFIRMED** as parser behavior; which of these branches executes for the frozen input remains **UNKNOWN**. Thus even a complete pair of source records would not by itself give the count or bytes of the emitted program.

`0x001fb7af` allocates `main_instruction_count * 8` bytes through the configured allocator and writes its pointer/count to the compiler result. It separately allocates `SA_update_count * 8` bytes when needed, emits through `0x001fa3ea`, and checks that emitted instruction count equals its precomputed count. The emitter walks lowered IR instructions; its leaf `0x002400eb` builds an assembler record via `0x0023d831` and invokes `0x0025309a`. That final encoder dispatches by the *lowered* assembler opcode, not the original Mesa or UniFlex opcode. The CPU output is deterministic for fully specified inputs, but the exact main/secondary instruction words, counts, register assignment and metadata for the frozen triangle are still **UNKNOWN**.

The selected parser path is narrower than the overall compiler graph. `0x001c22b0` handles UniFlex `0x48` as an ordinary instruction, rather than the `0x35` END control record. Its operand-category helper `0x001be5bc` checks the destination descriptor's `+0x08` word (record `+0x0c`), which remains zero for this MOV; the branch therefore calls `0x00219998`, the scalar floating-point lowering path, rather than either alternate category handler. There, opcode `0x48` selects internal opcode `1` and the four set destination-mask bits are visited separately. The routine creates per-component intermediate operations and may add further moves or coalesce components. **CONFIRMED:** four components enter this lowering, not that four final USSE instructions leave it. END creates a control-flow terminator in `0x001c22b0`; it is not itself proof of a final eight-byte instruction. This rules out deriving the final byte count from the two Mesa records.

The exact static frontier is now the state after `0x00219998`: its component operations pass through ELF VAs `0x00212b25`, `0x00211c4d` and `0x00214363` and then the passes in `0x001c606c`. `0x001c95f7` counts the transformed program only after those passes. No selected transformed-IR snapshot, post-allocation register map or final encoder inputs have been reconstructed. These facts are **not yet reverse-engineered from code present in this ELF**; they are not absent from the artifact or shown to require hardware observation.

The three helpers have now also been decompiled from the disposable read-only project. `0x00212b25` maps each selected source component by descriptor type and swizzle; `0x00211c4d` maps the destination and can update compiler-state masks; `0x00214363` can insert further intermediate instructions according to swizzle/format parameters. The call sites in `0x00219998` therefore need their **selected** descriptor and compiler-state values before their output IR can be counted. This is a more precise obstacle than the binary being stripped: the necessary functions are present, but the four-component path has not been symbolically evaluated through them and the subsequent optimization/allocator passes. None of these helpers is the final eight-byte encoder.

An instruction-level search of the retained ELF found the write to compiler-state `+0x60c` at ELF `0x001cab00`; the disposable Ghidra project locates it in function `0x001c95f7`, the final direct call of `0x001c606c`. The adjacent write at `0x001cab09` sets `+0x610` (label count). This narrows the main-count producer to a specific function and program point. It is still dependent on the prior transformed IR, so its value for the frozen program is not yet derivable merely from these stores.

At the end of `0x001c95f7`, the primary count is the accumulated `local_3c[0]` from traversal helper `0x001c72a1`; a separate pass sets the SA-update count. The function also records label count from `local_3c[4]`. Its earlier code can insert finalization instructions and depends on the transformed blocks, so treating the two Mesa instructions as a two-slot USSE program would be unsupported.

The targeted local search found no compiler implementation sources under `references/omap5-sgx-ddk-um-linux` or `references/omap5-sgx-ddk-linux` matching `usc`, `uniflex`, `useasm` or `psb_use` filenames; a C/H content search for `uPtPhase1Start`, `psb_use_mesa_fp.c` and `usc/hw.c` also returned no source. The OMAP5 userspace tree does include a `libusc.so.1.9.6.0` binary, which does not establish equivalence to this Poulsbo compiler. Narrow public searches for `psb_use_mesa_fp.c`, `usc/hw.c` with `uMainProgInstCount`, and `psb_use_compiler` returned no source. This does **not** mean static derivation from the retained ELF is impossible.
