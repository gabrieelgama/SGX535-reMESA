# SGX535 PDS historical public-document hunt

**P7H-059, 2026-09-27. Hunt level 1: a new historical public documentation path, but no target document.** This pass searched archival download infrastructure and document manifests for `Eurasia.3D Input Parameter Format.1.3.37a.SGX535 1.2.External.pdf`. The exact PDF, original URL, release bundle, and public distribution status remain **unknown**. No public Series5 PDS encoder was recovered. The [search ledger](sgx535-pds-document-hunt.csv) records bounded queries and the [source registry](sgx535-pds-document-sources.json) records recovered bytes, SHA-256 values, and provenance. The cache is outside the repository at `/tmp/sgx535-doc-hunt`; nothing was added to `references/`.

The [April 2009 PowerVR forum post](https://forums.imgtec.com/t/pds-programming/333) remains the only exact-filename citation found. Its author says the document discusses PDS programming and DS0/DS1. The vendor response directs the discussion to email. That exchange demonstrates a user possessed the document; it does **not** establish that its PDF was publicly distributed. The [USITC exhibit index](https://www.usitc.gov/intellectual_property/documents/pub4374_vol_2_of_2.pdf) separately lists an `Eurasia 3D Input Parameter Format` exhibit, but gives no revision match or public release and marks the exhibit withdrawn. Both citations predate this hunt and are not counted as recovered artifacts.

## New archival constraints

The Wayback Machine preserved the [March 2008 official SGX SDK page](https://web.archive.org/web/20080319032655id_/http://www.imgtec.com:80/powervr/insider/sdk/KhronosOpenGLES2xSGX.asp) and [SDK download index](https://web.archive.org/web/20080317214242id_/http://www.imgtec.com:80/powervr/insider/sdkdownloads/index.asp). Their Linux OpenGL ES 2.0 download points to a `powervr-login.asp?SDK=LinuxOGLES2` route. Captured [2009](https://web.archive.org/web/20090413233538id_/http://www.imgtec.com:80/PowerVR/insider/powervr-login.asp?SDK=LinuxOGLES2) and [2010](https://web.archive.org/web/20100211104125id_/http://www.imgtec.com:80/powerVR/insider/powervr-login.asp?SDK=LinuxOGLES2) versions are login forms, not archive-file links or proof that the requested PDS manual belonged to that SDK. The captured [2012 legacy SDK listing](https://web.archive.org/web/20120510031036id_/http://www.imgtec.com:80/PowerVR/insider/sdkdownloads/legacy.asp) likewise supplies no target-document title.

The archived, publicly linked [June 2011 SDK documentation index](https://web.archive.org/web/20110626090624id_/http://www.imgtec.com:80/powervr/insider/powervr-sdk-docs.asp) has 11 PDF links; the [January 2012 index](https://web.archive.org/web/20120103200626id_/http://www.imgtec.com:80/powervr/insider/powervr-sdk-docs.asp) has 22. A Wayback CDX query of the adjacent `powervr/insider/docs/` subtree returned 36 distinct archived URL keys, including 23 PDF captures with HTTP 200, but no Eurasia filename. Direct CDX requests for likely exact URLs under that directory and `Documentation/` returned no rows where completed; several requests timed out. These results exclude **those captured public indexes and paths only**, not the document's existence elsewhere or in an uncaptured private/partner directory.

An [official archived Series5 architecture guide](https://web.archive.org/web/20120417030743id_/http://www.imgtec.com:80/powervr/insider/docs/PowerVR%20Series%205.SGX%20Architecture%20Guide%20for%20Developers.1.0.13.External.pdf) gives a verified neighboring public document in the same tree. The 27-page guide's extracted text contains no `PDS`, `DS0`, `DS1`, or `Eurasia` term and its related-materials section does not point to the target. Its SHA-256 is `2ef561fc5486a462a3b39eef2579dd58f207eb390778e2b1112ddf3d7fc14fbb`. Its public status does **not** transfer to a different `External.pdf` document.

A [third-party Raspberry Pi SDK tree](https://github.com/anonymousjustice/pvr-pi/tree/master/SDKPackage_OGLES2/Documentation) includes a copy of that guide, but its README says the SDK was modified. The complete 3,043-entry Git tree has no pathname matching `Eurasia`, `PDS`, `Input Parameter`, or `assembler`. This is a bounded result for that modified tree, not a search of every original SDK release. The mirror PDF differs at the byte level from the official archive although extracted text matches; it is not used as implementation evidence.

CDX metadata for historical `ftp.imgtec.com/` and `downloads.imgtec.com/` prefixes returned no indexed URLs in the scoped requests. `ftp.powervr.com/` showed only a later `robots.txt` 404; the `ftp.videologic.com/` captures are older VideoLogic pages, not an identified SGX535 documentation route. A 2007 CDX set names `SDK_OGLES2_LINUX_PCEMULATION_2.01.21.0983.tar.gz` under `www.imgtec.com/powervr/insider/Downloads/` and `/register/`, but those captures are **404 pages**, not SDK package bytes. The exact file's CDX history has one recorded 404. Archive absence is not server-wide or historical absence. Later OpenEmbedded `img-pvr-sdk` 3.3.2 recipes and current PowerVR SDK manifests do not bind this 2009 manual to a release; the latter were already audited in P7H-058.

## Consequence

No recovered artifact supplies a new SGX535 PDS source/preload eligibility rule. **B1, L12, and R3 remain OPEN.** R1/B3 and R2/B4 also remain unchanged; the public architecture guide supplies neither completion contract. The static frozen triangle remains PARTIAL, complete mode REFUSES, Gate B is BLOCKED, whitelist `[]`, and no hardware was touched. The unseen target PDF is still **VERY LIKELY** to contain the relevant information class based only on the public forum description. Its actual coverage and distribution status remain unverified. A genuinely public PDS assembler with complete launch and operand contracts could independently resolve R3; none was located here.

**Best surviving lead:** the precise 2009 forum citation and its vendor-directed `devtech@imgtec.com` route. The new archive establishes where public SDK documentation lived, but its captured lists do not link this manual. The next concrete action is to request from Imagination a public-release copy or an explicit public-distribution statement for the exact filename and revision; only then inspect and apply its PDS rules.
